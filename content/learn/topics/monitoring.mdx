## OpenClaw 日志系统架构

一个完善的日志和监控体系是生产环境运维的核心基础设施。它能帮助你实时掌握系统健康状态、快速定位故障根因、发现性能瓶颈、验证变更效果。OpenClaw 的日志和监控架构分为三个层次：采集层、存储层和展示层。

```
┌───────────────────────────────────────────────────────────┐
│                    展示与告警层                              │
│   ┌──────────┐  ┌─────────────┐  ┌──────────────────┐    │
│   │  Grafana  │  │ AlertManager│  │ Telegram/DingTalk│    │
│   │ Dashboard │  │  告警路由     │  │    告警推送       │    │
│   └─────┬────┘  └──────┬──────┘  └────────┬─────────┘    │
├─────────┼──────────────┼──────────────────┼───────────────┤
│         │      存储与查询层                  │               │
│   ┌─────┴────┐  ┌──────┴──────┐            │              │
│   │Prometheus│  │    Loki     │            │              │
│   │ 指标存储  │  │  日志聚合    │            │              │
│   └─────┬────┘  └──────┬──────┘            │              │
├─────────┼──────────────┼───────────────────┼──────────────┤
│         │       采集层  │                    │              │
│   ┌─────┴────────┐ ┌──┴────────┐  ┌──────┴──────┐       │
│   │ Node Exporter│ │  Promtail │  │ cAdvisor    │       │
│   │  系统指标     │ │  日志采集   │  │ 容器指标     │       │
│   └──────────────┘ └───────────┘  └─────────────┘       │
│                                                           │
│   ┌──────────────────────────────────────────────────┐   │
│   │              OpenClaw Application                 │   │
│   │  stdout/stderr → JSON logs → /var/log/openclaw/  │   │
│   └──────────────────────────────────────────────────┘   │
└───────────────────────────────────────────────────────────┘
```

## 日志收集配置

### 日志级别与格式

OpenClaw 使用结构化 JSON 日志格式，便于机器解析和全文检索：

```json
{
  "timestamp": "2026-01-30T10:15:30.123Z",
  "level": "info",
  "service": "openclaw",
  "module": "agent-runtime",
  "traceId": "abc123def456",
  "message": "Agent 任务执行完成",
  "context": {
    "agentId": "code-reviewer",
    "taskId": "task-789",
    "duration": 3420,
    "tokensUsed": 2850,
    "model": "claude-sonnet-4-20250514"
  }
}
```

在 OpenClaw 配置中设置日志级别和输出：

```yaml
# config/logging.yaml

logging:
  # 全局日志级别: debug, info, warn, error
  level: "info"

  # 模块级别覆盖
  modules:
    agent-runtime: "info"
    mcp-client: "warn"
    skill-runtime: "info"
    http-server: "info"
    database: "warn"

  # 输出目标
  outputs:
    # 标准输出（Docker 日志驱动收集）
    stdout:
      enabled: true
      format: "json"

    # 文件输出（本地持久化）
    file:
      enabled: true
      path: "/var/log/openclaw/app.log"
      format: "json"
      rotation:
        max_size: "100MB"
        max_files: 10
        max_age: "30d"
        compress: true

  # 敏感信息过滤
  redaction:
    enabled: true
    fields:
      - "password"
      - "apiKey"
      - "token"
      - "authorization"
    replacement: "***REDACTED***"
```

## 关键监控指标

OpenClaw 生产环境需要重点监控以下指标：

| 指标类型 | 指标名称 | 告警阈值 | 说明 |
|---------|---------|---------|------|
| 系统 | CPU 使用率 | > 80% 持续 5 分钟 | 可能需要扩容 |
| 系统 | 内存使用率 | > 85% 持续 5 分钟 | 内存泄漏风险 |
| 系统 | 磁盘使用率 | > 90% | 需要清理或扩容 |
| 应用 | API 请求延迟 P95 | > 5s | 性能退化 |
| 应用 | API 错误率 | > 5% | 服务异常 |
| 应用 | 活跃连接数 | > 1000 | 连接池压力 |
| 应用 | Token 消耗速率 | 超过日预算 80% | 成本风控 |
| 数据库 | 连接数 | > 最大连接的 80% | 连接池耗尽 |
| 数据库 | 查询延迟 P95 | > 1s | 慢查询 |
| 容器 | 重启次数 | > 3 次 / 小时 | 应用不稳定 |

## 告警规则配置

```yaml
# config/alert-rules.yml

groups:
  - name: openclaw-system
    interval: 30s
    rules:
      # CPU 使用率过高
      - alert: HighCpuUsage
        expr: 100 - (avg by(instance) (irate(node_cpu_seconds_total{mode="idle"}[5m])) * 100) > 80
        for: 5m
        labels:
          severity: warning
          service: openclaw
        annotations:
          summary: "CPU 使用率过高"
          description: "实例 {{ $labels.instance }} CPU 使用率达到 {{ $value | printf \"%.1f\" }}%，持续超过 5 分钟"

      # 内存使用率过高
      - alert: HighMemoryUsage
        expr: (1 - node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes) * 100 > 85
        for: 5m
        labels:
          severity: warning
          service: openclaw
        annotations:
          summary: "内存使用率过高"
          description: "实例 {{ $labels.instance }} 内存使用率达到 {{ $value | printf \"%.1f\" }}%"

      # 磁盘空间不足
      - alert: DiskSpaceLow
        expr: (1 - node_filesystem_avail_bytes{mountpoint="/"} / node_filesystem_size_bytes{mountpoint="/"}) * 100 > 90
        for: 1m
        labels:
          severity: critical
          service: openclaw
        annotations:
          summary: "磁盘空间严重不足"
          description: "磁盘使用率达到 {{ $value | printf \"%.1f\" }}%，请立即处理"

  - name: openclaw-application
    interval: 15s
    rules:
      # API 延迟过高
      - alert: HighApiLatency
        expr: histogram_quantile(0.95, rate(openclaw_http_request_duration_seconds_bucket[5m])) > 5
        for: 3m
        labels:
          severity: warning
          service: openclaw
        annotations:
          summary: "API 响应延迟过高"
          description: "P95 延迟达到 {{ $value | printf \"%.2f\" }} 秒"

      # API 错误率过高
      - alert: HighErrorRate
        expr: sum(rate(openclaw_http_requests_total{status=~"5.."}[5m])) / sum(rate(openclaw_http_requests_total[5m])) * 100 > 5
        for: 3m
        labels:
          severity: critical
          service: openclaw
        annotations:
          summary: "API 错误率过高"
          description: "5xx 错误率达到 {{ $value | printf \"%.1f\" }}%"

      # 服务不可用
      - alert: ServiceDown
        expr: up{job="openclaw"} == 0
        for: 1m
        labels:
          severity: critical
          service: openclaw
        annotations:
          summary: "OpenClaw 服务不可用"
          description: "OpenClaw 主服务已停止响应，请立即检查"

      # Agent 执行超时
      - alert: AgentExecutionTimeout
        expr: rate(openclaw_agent_execution_timeout_total[5m]) > 0.1
        for: 5m
        labels:
          severity: warning
          service: openclaw
        annotations:
          summary: "Agent 执行超时频繁"
          description: "Agent 超时率: {{ $value | printf \"%.2f\" }} 次/秒"

      # Token 消耗过快
      - alert: HighTokenConsumption
        expr: sum(increase(openclaw_token_usage_total[1h])) > 100000
        for: 0m
        labels:
          severity: warning
          service: openclaw
        annotations:
          summary: "Token 消耗速率异常"
          description: "过去 1 小时消耗 {{ $value | printf \"%.0f\" }} tokens"

  - name: openclaw-database
    interval: 30s
    rules:
      # 数据库连接数过高
      - alert: DatabaseConnectionsHigh
        expr: pg_stat_activity_count > 80
        for: 5m
        labels:
          severity: warning
          service: postgresql
        annotations:
          summary: "数据库连接数过高"
          description: "当前活跃连接: {{ $value }}"

      # 慢查询
      - alert: SlowQueries
        expr: rate(pg_stat_activity_max_tx_duration{datname="openclaw"}[5m]) > 1
        for: 5m
        labels:
          severity: warning
          service: postgresql
        annotations:
          summary: "检测到慢查询"
          description: "数据库存在长时间运行的查询"

  - name: openclaw-containers
    interval: 30s
    rules:
      # 容器频繁重启
      - alert: ContainerRestartFrequent
        expr: increase(container_restart_count{name=~"openclaw.*"}[1h]) > 3
        for: 0m
        labels:
          severity: critical
          service: openclaw
        annotations:
          summary: "容器频繁重启"
          description: "容器 {{ $labels.name }} 在过去 1 小时内重启了 {{ $value }} 次"

      # 容器内存超限
      - alert: ContainerMemoryOverLimit
        expr: container_memory_usage_bytes{name=~"openclaw.*"} / container_spec_memory_limit_bytes{name=~"openclaw.*"} > 0.9
        for: 5m
        labels:
          severity: warning
          service: openclaw
        annotations:
          summary: "容器内存接近上限"
          description: "容器 {{ $labels.name }} 内存使用率达到 {{ $value | printf \"%.1f\" }}%"
```

## AlertManager 配置

```yaml
# config/alertmanager.yml

global:
  resolve_timeout: 5m

# 告警路由
route:
  group_by: ['alertname', 'service']
  group_wait: 30s
  group_interval: 5m
  repeat_interval: 4h
  receiver: 'default'

  routes:
    # 严重告警：立即发送到 Telegram 和钉钉
    - match:
        severity: critical
      receiver: 'critical-alerts'
      group_wait: 10s
      repeat_interval: 1h

    # 警告级别：发送到钉钉
    - match:
        severity: warning
      receiver: 'warning-alerts'
      group_wait: 1m
      repeat_interval: 4h

# 告警接收器
receivers:
  - name: 'default'
    webhook_configs:
      - url: 'http://alert-bridge:9095/dingtalk'

  - name: 'critical-alerts'
    webhook_configs:
      # Telegram Bot 告警
      - url: 'http://alert-bridge:9095/telegram'
        send_resolved: true
      # 钉钉告警
      - url: 'http://alert-bridge:9095/dingtalk'
        send_resolved: true

  - name: 'warning-alerts'
    webhook_configs:
      - url: 'http://alert-bridge:9095/dingtalk'
        send_resolved: true

# 抑制规则（避免告警风暴）
inhibit_rules:
  # 当 critical 告警触发时，抑制相同服务的 warning 告警
  - source_match:
      severity: 'critical'
    target_match:
      severity: 'warning'
    equal: ['service']
```

## 集成 Telegram / 钉钉告警推送

由于 AlertManager 不直接支持 Telegram 和钉钉，需要一个告警桥接服务：

```typescript
// alert-bridge/src/index.ts
// 告警桥接服务：将 AlertManager Webhook 转发到 Telegram 和钉钉

import http from 'node:http';

const TELEGRAM_BOT_TOKEN = process.env.TELEGRAM_BOT_TOKEN || '';
const TELEGRAM_CHAT_ID = process.env.TELEGRAM_CHAT_ID || '';
const DINGTALK_WEBHOOK = process.env.DINGTALK_WEBHOOK || '';
const DINGTALK_SECRET = process.env.DINGTALK_SECRET || '';

interface AlertManagerPayload {
  status: 'firing' | 'resolved';
  alerts: Array<{
    status: string;
    labels: Record<string, string>;
    annotations: Record<string, string>;
    startsAt: string;
    endsAt: string;
  }>;
}

// 格式化告警消息
function formatAlert(payload: AlertManagerPayload): string {
  const { status, alerts } = payload;
  const emoji = status === 'firing' ? '🔴' : '✅';
  const statusText = status === 'firing' ? '触发' : '已恢复';

  const lines = [`${emoji} 告警${statusText} (${alerts.length} 条)`];
  lines.push(`时间: ${new Date().toLocaleString('zh-CN', { timeZone: 'Asia/Shanghai' })}`);
  lines.push('');

  for (const alert of alerts) {
    lines.push(`📋 ${alert.labels.alertname}`);
    lines.push(`   严重等级: ${alert.labels.severity}`);
    lines.push(`   服务: ${alert.labels.service || 'unknown'}`);
    if (alert.annotations.summary) {
      lines.push(`   摘要: ${alert.annotations.summary}`);
    }
    if (alert.annotations.description) {
      lines.push(`   详情: ${alert.annotations.description}`);
    }
    lines.push('');
  }

  return lines.join('\n');
}

// 发送到 Telegram
async function sendTelegram(message: string): Promise<void> {
  const url = `https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/sendMessage`;
  await fetch(url, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      chat_id: TELEGRAM_CHAT_ID,
      text: message,
      parse_mode: 'HTML',
    }),
  });
}

// 发送到钉钉
async function sendDingTalk(message: string): Promise<void> {
  // 计算签名
  const timestamp = Date.now();
  const crypto = await import('node:crypto');
  const stringToSign = `${timestamp}\n${DINGTALK_SECRET}`;
  const sign = encodeURIComponent(
    crypto.createHmac('sha256', DINGTALK_SECRET)
      .update(stringToSign)
      .digest('base64')
  );

  const url = `${DINGTALK_WEBHOOK}&timestamp=${timestamp}&sign=${sign}`;
  await fetch(url, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      msgtype: 'text',
      text: { content: message },
    }),
  });
}

// HTTP 服务器
const server = http.createServer(async (req, res) => {
  if (req.method !== 'POST') {
    res.writeHead(405);
    res.end('Method Not Allowed');
    return;
  }

  let body = '';
  req.on('data', (chunk) => { body += chunk; });
  req.on('end', async () => {
    try {
      const payload: AlertManagerPayload = JSON.parse(body);
      const message = formatAlert(payload);

      if (req.url === '/telegram') {
        await sendTelegram(message);
      } else if (req.url === '/dingtalk') {
        await sendDingTalk(message);
      } else {
        // 默认发送到所有渠道
        await Promise.allSettled([
          sendTelegram(message),
          sendDingTalk(message),
        ]);
      }

      res.writeHead(200);
      res.end('OK');
    } catch (error) {
      console.error('处理告警失败:', error);
      res.writeHead(500);
      res.end('Internal Server Error');
    }
  });
});

server.listen(9095, () => {
  console.log('Alert Bridge 服务已启动，监听端口 9095');
});
```

## 日志分析与故障排查

### 常用排查命令

```bash
# 查看 OpenClaw 实时日志
docker logs -f openclaw-openclaw-1 --tail 100

# 按错误级别过滤
docker logs openclaw-openclaw-1 2>&1 | jq 'select(.level == "error")'

# 查看特定时间范围的错误
docker logs openclaw-openclaw-1 --since "2026-01-30T10:00:00" --until "2026-01-30T11:00:00" 2>&1 \
  | jq 'select(.level == "error") | {time: .timestamp, msg: .message, ctx: .context}'

# 统计各级别日志数量
docker logs openclaw-openclaw-1 2>&1 | jq -r '.level' | sort | uniq -c | sort -rn

# 查看最近的 Agent 执行错误
docker logs openclaw-openclaw-1 2>&1 \
  | jq 'select(.module == "agent-runtime" and .level == "error") | {time: .timestamp, agent: .context.agentId, error: .message}'

# 查看 API 慢请求（超过 3 秒）
docker logs openclaw-openclaw-1 2>&1 \
  | jq 'select(.module == "http-server" and .context.duration > 3000) | {path: .context.path, duration: .context.duration, time: .timestamp}'

# 使用 Loki LogQL 查询（通过 Grafana 或 logcli）
# 查看最近 1 小时的错误日志
logcli query '{service="openclaw"} |= "error"' --since=1h --limit=50

# 按 traceId 追踪完整请求链路
logcli query '{service="openclaw"} | json | traceId="abc123def456"' --since=24h
```

## 总结

通过本教程搭建的监控体系，你将获得以下能力：

1. **实时日志收集**：通过 Promtail + Loki 实现所有日志的集中化管理
2. **全方位指标监控**：Prometheus 采集系统、应用、数据库、容器的全维度指标
3. **可视化仪表盘**：Grafana Dashboard 提供直观的运行状态展示
4. **智能告警**：基于规则的告警配置，通过 Telegram 和钉钉实时推送
5. **Uptime 监控**：从外部视角持续检测服务可用性
6. **故障排查**：结构化日志和链路追踪加速问题定位

建议在部署完成后进行一次完整的告警测试（手动触发各级别告警），确认所有通知渠道正常工作。日常运维中养成每天查看 Dashboard 的习惯，对异常趋势保持敏感，将问题消灭在萌芽阶段。
