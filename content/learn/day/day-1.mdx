## 欢迎来到 OpenClaw 的世界

你是否曾经幻想过拥有一个无所不能的 AI 助手？一个能帮你写代码、搜索信息、管理文件、甚至自动化日常工作的智能伙伴？OpenClaw 就是这样一个强大的开源 AI 助手框架，它让每个人都能拥有属于自己的 AI 工作站。

在今天的课程中，你将从零开始了解 OpenClaw 的设计理念，完成完整的安装部署流程，并亲手发起你与 AI 助手的第一次对话。无论你是开发老手还是刚入门的新人，这份指南都会带你稳稳地迈出第一步。

### 什么是 OpenClaw？

OpenClaw 是一款基于大语言模型的智能助手平台，它不仅仅是一个聊天机器人——它是一个完整的 AI 工作框架，能让你在终端中完成几乎所有需要 AI 协助的任务。

你可能已经用过市面上的一些 AI 工具，比如 ChatGPT、GitHub Copilot 或者百度文心一言。那么 OpenClaw 和它们有什么不同？我们来做一个简单的对比：

| 特性 | ChatGPT | GitHub Copilot | OpenClaw |
|------|---------|----------------|----------|
| 使用方式 | 网页/App | IDE 插件 | CLI + 本地引擎 |
| 开源免费 | 否 | 否 | 是 |
| 本地部署 | 不支持 | 不支持 | 完全支持 |
| 自定义技能 | 有限（GPTs） | 不支持 | ClawHub 生态 |
| 文件操作 | 受限 | 仅代码补全 | 完整读写权限 |
| 多模型切换 | 仅 OpenAI | 仅 Copilot | 任意模型 |
| 自动化任务 | 不支持 | 不支持 | 内置调度器 |
| 数据隐私 | 数据上传云端 | 代码上传云端 | 可完全本地化 |

简单来说，ChatGPT 像是一个网页上的智能客服，Copilot 像是一个只懂代码补全的插件，而 OpenClaw 是一把真正交到你手里的「AI 瑞士军刀」——你可以自由定制、自主掌控、无限扩展。

#### 开源理念

OpenClaw 从第一行代码开始就坚持完全开源。这意味着：

- **透明可审计**：所有代码公开在 GitHub 上，任何人都可以检查安全性
- **社区驱动**：功能优先级由社区投票决定，而非商业公司的利润目标
- **数据自主**：你的对话记录、配置文件、自定义技能全部存储在本地，不上传任何第三方服务器
- **自由分发**：基于 Apache 2.0 协议，你可以在个人项目和商业项目中自由使用

如果你关心数据隐私，或者需要在内网环境中部署 AI 助手，OpenClaw 几乎是目前最理想的选择。

#### 架构概览

OpenClaw 采用三层架构设计，每一层各司其职：

```
┌─────────────────────────────────────────┐
│             CLI（命令行界面）              │
│   用户交互入口，处理输入输出和终端渲染       │
├─────────────────────────────────────────┤
│           Engine（核心引擎）               │
│   对话管理、模型调度、上下文处理、任务编排    │
├─────────────────────────────────────────┤
│           Skills（技能层）                 │
│   文件操作、联网搜索、代码执行、社区扩展      │
└─────────────────────────────────────────┘
```

- **CLI（命令行界面）**：这是你与 OpenClaw 交互的入口。所有命令都通过 `openclaw` 这个命令行工具发起，它负责接收你的输入、渲染 AI 的回复、展示进度和状态信息。
- **Engine（核心引擎）**：这是 OpenClaw 的大脑。它管理对话上下文、调度底层语言模型、编排多步骤任务、处理并发请求。你可以把它理解为一个智能中间件。
- **Skills（技能层）**：这是 OpenClaw 的双手。每个技能（Skill）是一个独立的功能模块——读写文件是一个技能，联网搜索是一个技能，执行代码也是一个技能。你可以通过 ClawHub 安装社区贡献的技能包来扩展能力。

这三层松耦合的设计让你可以单独升级某一层而不影响其他部分。比如，你可以切换底层模型而不需要重新配置技能，也可以安装新技能而不需要更新引擎。

### 核心功能一览

OpenClaw 提供六大核心能力，覆盖从日常对话到复杂自动化的各类场景：

| 能力 | 说明 | 示例 |
|------|------|------|
| **深度对话** | 支持多轮复杂对话，理解上下文语境，自动维护会话记忆 | 「帮我分析这段代码的时间复杂度，然后给出优化方案」 |
| **文件与代码操作** | 直接读写本地文件、生成和修改代码、批量重命名 | 「把 src 目录下所有 .js 文件转换为 TypeScript」 |
| **联网搜索** | 实时获取互联网信息，调用外部 API，抓取网页内容 | 「搜索 Rust 最新的异步运行时对比，整理成表格」 |
| **技能扩展** | 通过 ClawHub 安装社区开发的各类技能包，一键获取新能力 | `openclaw skill install @community/translator` |
| **自动化任务** | 定时执行任务、文件监听触发、流水线编排 | 「每天早上 9 点抓取竞品的价格变动并发送报告」 |
| **多 Agent 协作** | 多个 AI 代理角色分工协同完成复杂任务 | 「让产品经理 Agent 和开发 Agent 一起讨论这个需求」 |

在后续的课程中，我们会逐一深入学习每一项能力。今天的重点是把环境搭起来，让一切先跑通。

### 环境准备

在开始安装之前，请确保你的系统满足以下基本要求：

- **操作系统**：Linux（推荐 Ubuntu 22.04+）、macOS 12+ 或 Windows 11（WSL2）
- **硬件配置**：至少 4GB 内存，10GB 可用磁盘空间
- **软件依赖**：Node.js 18+、Git 2.30+、Docker（可选但推荐）
- **网络环境**：能够访问 GitHub 和 npm 仓库（国内用户请参考后续的镜像配置部分）

下面按操作系统分别说明环境准备步骤。

#### Ubuntu / Debian

Ubuntu 是 OpenClaw 开发和测试的首选环境，兼容性最好。

```bash
# 更新系统包
sudo apt update && sudo apt upgrade -y

# 安装基础依赖
sudo apt install -y curl git build-essential

# 安装 Node.js 18（通过 NodeSource）
curl -fsSL https://deb.nodesource.com/setup_18.x | sudo -E bash -
sudo apt install -y nodejs

# 验证安装
node --version   # 应输出 v18.x.x 或更高
npm --version    # 应输出 9.x.x 或更高
git --version    # 应输出 2.30 或更高
```

如果你的 Ubuntu 版本较旧（20.04 或更早），系统自带的 Node.js 版本可能不够新。务必通过 NodeSource 仓库安装，不要使用 `apt install nodejs` 直接安装。

#### macOS

macOS 用户推荐使用 Homebrew 管理依赖。

```bash
# 安装 Homebrew（如果尚未安装）
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# 安装 Node.js 和 Git
brew install node git

# 验证安装
node --version   # 应输出 v18.x.x 或更高
npm --version
git --version
```

注意：macOS 自带的 Git 版本通常是 Apple 定制版，功能上没有问题，但如果你需要最新特性，建议通过 Homebrew 安装。

#### Windows（WSL2）

OpenClaw 不直接支持 Windows 原生环境，你需要通过 WSL2 来运行。

```powershell
# 在 PowerShell（管理员模式）中执行
wsl --install -d Ubuntu-22.04
```

安装完成并重启后，打开 Ubuntu 终端，按照上面 Ubuntu 的步骤安装 Node.js 和 Git 即可。

**WSL2 额外注意事项**：

- 确保 WSL 版本是 2 而非 1：运行 `wsl --list --verbose` 检查，VERSION 列应显示 2
- 建议将项目文件存储在 WSL 文件系统内（`/home/你的用户名/` 路径下），而非 Windows 挂载盘（`/mnt/c/`），否则文件 IO 性能会大幅下降
- 如果需要使用 Docker，安装 Docker Desktop 并在设置中启用 WSL2 集成

#### 依赖检查清单

在继续安装之前，运行以下命令确认所有依赖就绪：

```bash
echo "=== 环境检查 ==="
echo "Node.js: $(node --version 2>/dev/null || echo '未安装')"
echo "npm:     $(npm --version 2>/dev/null || echo '未安装')"
echo "Git:     $(git --version 2>/dev/null || echo '未安装')"
echo "Docker:  $(docker --version 2>/dev/null || echo '未安装（可选）')"
```

所有必需项都显示版本号后，就可以进入安装环节了。

### 快速安装

OpenClaw 提供三种安装方式，根据你的需求选择合适的方式。

#### 方式一：使用安装脚本（推荐新手）

这是最简单的安装方式，脚本会自动检测环境并完成所有配置：

```bash
curl -fsSL https://get.openclaw.dev | bash
```

脚本执行过程中会显示安装进度。完成后你应该看到类似输出：

```
[OK] Node.js 18.19.0 已检测
[OK] 依赖安装完成
[OK] OpenClaw CLI v1.2.0 已安装
[OK] 已添加到 PATH

运行 openclaw init 开始初始化配置。
```

#### 方式二：使用 npm 全局安装

如果你熟悉 Node.js 生态，可以直接通过 npm 安装：

```bash
npm install -g @openclaw/cli
```

安装完成后验证：

```bash
openclaw --version
# 输出示例：openclaw/1.2.0 linux-x64 node-v18.19.0
```

如果遇到权限问题，不要使用 `sudo npm install -g`，而是修复 npm 全局目录的权限：

```bash
mkdir -p ~/.npm-global
npm config set prefix '~/.npm-global'
echo 'export PATH=~/.npm-global/bin:$PATH' >> ~/.bashrc
source ~/.bashrc

# 然后重新安装
npm install -g @openclaw/cli
```

#### 方式三：Docker 安装

如果你不想在系统上安装 Node.js，或者希望保持环境隔离，Docker 是一个理想选择：

```bash
# 拉取官方镜像
docker pull openclaw/openclaw:latest

# 运行容器（挂载配置目录和工作目录）
docker run -it \
  -v ~/.openclaw:/root/.openclaw \
  -v $(pwd):/workspace \
  openclaw/openclaw:latest
```

你也可以为 Docker 运行方式创建一个便捷的 alias：

```bash
echo 'alias openclaw="docker run -it -v ~/.openclaw:/root/.openclaw -v \$(pwd):/workspace openclaw/openclaw:latest"' >> ~/.bashrc
source ~/.bashrc
```

这样之后直接输入 `openclaw` 就能启动容器化的 OpenClaw 了。

#### 方式四：从源码构建

如果你想使用最新的开发版本，或者打算参与 OpenClaw 的开发贡献，可以从源码构建：

```bash
# 克隆仓库
git clone https://github.com/openclaw/openclaw.git
cd openclaw

# 安装依赖
npm install

# 构建项目
npm run build

# 链接到全局
npm link

# 验证
openclaw --version
```

从源码构建适合想要深入了解内部实现或提交代码贡献的开发者。日常使用推荐前三种方式。

#### 国内用户镜像与代理配置

如果你在国内网络环境下遇到下载缓慢或连接超时的问题，可以配置镜像源加速：

```bash
# 配置 npm 镜像（淘宝源）
npm config set registry https://registry.npmmirror.com

# 配置 OpenClaw 下载镜像
export OPENCLAW_MIRROR=https://mirror.openclaw.dev

# 如果使用安装脚本，可以指定镜像
curl -fsSL https://get.openclaw.dev | OPENCLAW_MIRROR=https://mirror.openclaw.dev bash
```

如果你使用代理，可以设置 HTTP 代理环境变量：

```bash
export HTTP_PROXY=http://127.0.0.1:7890
export HTTPS_PROXY=http://127.0.0.1:7890

# 然后正常执行安装命令
npm install -g @openclaw/cli
```

建议将镜像和代理配置写入 `~/.bashrc` 或 `~/.zshrc`，避免每次都要手动设置。

### 初始化配置详解

安装完成后，运行初始化向导来完成首次配置：

```bash
openclaw init
```

向导会依次引导你完成以下几个步骤：

#### 第一步：选择默认模型

```
? 请选择默认语言模型：
  > gpt-4（推荐，综合能力最强）
    gpt-3.5-turbo（速度快，成本低）
    claude-3-opus（擅长分析和推理）
    claude-3-sonnet（均衡之选）
    本地模型（Ollama / LM Studio）
    自定义 API 端点
```

如果你不确定选哪个，先选 `gpt-4` 或 `claude-3-sonnet`。后续随时可以通过 `openclaw config set model <模型名>` 切换。

如果你想使用本地模型（例如 Llama、Qwen 等通过 Ollama 运行的模型），选择「本地模型」后需要填写本地服务的地址，默认为 `http://localhost:11434`。

#### 第二步：配置 API 密钥

```
? 请输入你的 API Key：
  sk-xxxxxxxxxxxxxxxxxxxxxxxx
```

根据你选择的模型提供商，输入对应的 API 密钥。密钥会加密存储在 `~/.openclaw/credentials` 文件中。

如果你暂时没有 API 密钥，可以按回车跳过此步骤。OpenClaw 提供了每日有限额度的试用密钥，足够你完成本教程的学习。

#### 第三步：语言偏好

```
? 请选择界面和默认回复语言：
  > 中文（简体）
    中文（繁体）
    English
    日本語
    자동 감지
```

这里设置的是 OpenClaw 界面文本和 AI 默认回复的语言。选择「中文（简体）」后，AI 会默认用中文回复你的问题，当然你也可以在对话中随时用其他语言提问。

#### 第四步：默认工作空间

```
? 请设置默认工作目录：
  > /home/你的用户名/openclaw-workspace
    当前目录
    自定义路径
```

工作空间（Workspace）是 OpenClaw 管理项目文件和对话上下文的目录。建议设置一个专门的目录，保持工作区整洁。

初始化完成后，你会看到配置摘要：

```
=== OpenClaw 初始化完成 ===
默认模型：  gpt-4
语言偏好：  中文（简体）
工作目录：  /home/user/openclaw-workspace
配置文件：  ~/.openclaw/config.yaml

运行 openclaw chat 开始你的第一次对话。
```

所有配置都保存在 `~/.openclaw/config.yaml` 中，你可以随时手动编辑这个文件来调整设置。

### 第一次对话

配置完成后，让我们正式开始与 OpenClaw 对话。在终端中输入：

```bash

```

你会进入一个交互式对话界面。下面通过几个例子来展示 OpenClaw 的不同能力。

输入一条简单的问候，感受 OpenClaw 的响应速度和对话质量：

```
You > 你好，请介绍一下你自己

OpenClaw > 你好！我是 OpenClaw，一个运行在你本地环境中的 AI 助手。
我可以帮你完成很多事情，包括：
- 回答各类问题和进行深度讨论
- 读写和分析本地文件
- 搜索互联网获取最新信息
- 生成和修改代码
- 执行自动化任务

```

#### 示例二：文件操作

OpenClaw 可以直接操作你系统中的文件。试试让它帮你查看一个文件：

```
You > 请读取 ~/.openclaw/config.yaml 的内容，并解释每个配置项的含义

OpenClaw > 好的，让我读取这个文件的内容。

[读取文件] ~/.openclaw/config.yaml

文件内容如下：

  model: gpt-4
  language: zh-CN
  workspace: /home/user/openclaw-workspace
  temperature: 0.7
  max_tokens: 4096

各配置项说明：
- model: 当前使用的语言模型，gpt-4 是 OpenAI 的旗舰模型

- workspace: 默认工作空间路径
- temperature: 生成随机性参数，0.7 是一个兼顾创造性和稳定性的值
- max_tokens: 单次回复的最大 token 数量
```

#### 示例三：联网搜索

OpenClaw 可以实时搜索互联网获取最新信息：

```
You > 帮我搜索一下 Rust 语言 2025 年的最新稳定版本是多少

OpenClaw > 让我帮你搜索这个信息。

[搜索中] Rust latest stable version 2025...

根据搜索结果，Rust 最新的稳定版本是 1.84.0，发布于 2025 年 1 月。
主要更新包括：
- 新增 trait 关联类型的默认值支持
- 标准库中新增了若干稳定化的 API
- 编译器性能优化，增量编译速度提升约 15%

你可以通过 rustup update 命令升级到最新版本。
```

#### 示例四：获取帮助

如果你不确定 OpenClaw 能做什么，可以直接问它：

```
You > /help

OpenClaw > 以下是常用命令列表：

  /help         显示帮助信息
  /model        查看或切换当前模型

你也可以直接用自然语言描述你的需求，我会自动选择合适的方式来完成。
```

完成以上体验后，输入 `/exit` 或按 `Ctrl+D` 退出对话界面。

### 验证安装

为了确保所有组件正常工作，OpenClaw 提供了一个自检工具。运行以下命令：

```bash
openclaw doctor
```

这个命令会对系统环境、依赖组件和网络连接进行全面检查。正常情况下，你应该看到类似输出：

```
OpenClaw Doctor v1.2.0
======================

[PASS] Node.js 版本              v18.19.0 (>= 18.0.0)
[PASS] npm 版本                  9.2.0 (>= 9.0.0)
[PASS] Git 版本                  2.42.0 (>= 2.30.0)
[PASS] 磁盘空间                  可用 45.2 GB (>= 10 GB)
[PASS] 配置文件                  ~/.openclaw/config.yaml 存在且格式正确
[PASS] API 密钥                  已配置，密钥有效
[PASS] 模型连接测试              gpt-4 响应正常 (延迟 320ms)
[PASS] 技能引擎                  已加载 12 个内置技能
[PASS] 工作空间                  /home/user/openclaw-workspace 可读写
[INFO] Docker                   已安装 (v24.0.7)，容器化技能可用

检查完成：9 项通过，0 项失败，1 项提示
```

**各检查项含义说明**：

- **Node.js / npm / Git 版本**：检查必需的运行时依赖是否满足最低版本要求
- **磁盘空间**：确保有足够的磁盘空间存储对话记录和缓存
- **配置文件**：验证配置文件是否存在且 YAML 格式正确
- **API 密钥**：验证密钥是否已配置，并尝试向模型提供商发送一个测试请求
- **模型连接测试**：实际调用模型 API 进行一次小型推理，确认端到端连接正常
- **技能引擎**：检查内置技能模块是否完整加载
- **工作空间**：验证工作目录是否存在且具有读写权限

如果某一项显示 `[FAIL]`，说明该组件有问题，doctor 会在下方给出修复建议。

你也可以手动进行几项基础验证：

```bash
# 验证 CLI 是否在 PATH 中
which openclaw

# 验证配置文件是否存在
ls -la ~/.openclaw/config.yaml

# 验证工作空间目录是否可写
touch ~/.openclaw/.write_test && rm ~/.openclaw/.write_test && echo "可写"
```

### 常见安装问题排查

在安装过程中，你可能会遇到一些问题。下面列出最常见的几种情况及解决方案。

#### 问题一：Node.js 版本不匹配

**症状**：运行 `openclaw` 时报错 `SyntaxError: Unexpected token` 或 `This module requires Node.js >= 18`。

**原因**：系统安装的 Node.js 版本低于 18，不支持 OpenClaw 使用的语法特性。

**解决方案**：

```bash
# 检查当前版本
node --version

# 如果低于 v18，使用 nvm 安装新版本
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
source ~/.bashrc
nvm install 18
nvm use 18
nvm alias default 18

# 然后重新安装 OpenClaw
npm install -g @openclaw/cli
```

#### 问题二：网络连接超时

**症状**：`npm install` 过程中长时间无响应，最终提示 `ETIMEDOUT` 或 `ECONNRESET`。

**原因**：国内网络环境访问 npm 官方仓库速度不稳定。

**解决方案**：

```bash
# 切换到淘宝镜像源
npm config set registry https://registry.npmmirror.com

# 清除缓存后重试
npm cache clean --force
npm install -g @openclaw/cli

# 如果仍然失败，尝试使用代理
export HTTPS_PROXY=http://你的代理地址:端口
npm install -g @openclaw/cli
```

#### 问题三：权限错误（EACCES）

**症状**：`npm install -g` 时报错 `Error: EACCES: permission denied`。

**原因**：npm 全局安装目录需要 root 权限，但直接使用 `sudo` 安装可能导致后续权限混乱。

**解决方案**：

```bash
# 创建用户级全局目录（推荐方案）
mkdir -p ~/.npm-global
npm config set prefix '~/.npm-global'

# 添加到 PATH
echo 'export PATH=~/.npm-global/bin:$PATH' >> ~/.bashrc
source ~/.bashrc

# 重新安装
npm install -g @openclaw/cli
```

#### 问题四：Docker 相关问题

**症状**：使用 Docker 方式安装时报错 `Cannot connect to the Docker daemon` 或 `permission denied`。

**原因**：Docker 服务未启动，或者当前用户没有被添加到 docker 用户组。

**解决方案**：

```bash
# 确保 Docker 服务正在运行
sudo systemctl start docker
sudo systemctl enable docker

# 将当前用户添加到 docker 组（免 sudo 运行 Docker）
sudo usermod -aG docker $USER

# 重新登录终端使权限生效（或运行以下命令）
newgrp docker

# 验证
docker run hello-world
```

#### 问题五：openclaw init 卡住或报错

**症状**：运行 `openclaw init` 后向导界面不响应，或提示 `Failed to fetch model list`。

**原因**：初始化过程需要连接 OpenClaw 的配置服务器获取可用模型列表，网络不通会导致卡住。

**解决方案**：

```bash
# 使用离线模式初始化（跳过在线检查）
openclaw init --offline

# 手动创建配置文件
mkdir -p ~/.openclaw
cat > ~/.openclaw/config.yaml << 'EOF'
model: gpt-4
language: zh-CN
workspace: ~/openclaw-workspace
temperature: 0.7
max_tokens: 4096
EOF

# 单独配置 API 密钥
openclaw config set api_key sk-你的密钥
```

```bash
openclaw doctor > ~/doctor-report.txt
```

**练习二：基础对话探索**

进入 `openclaw chat`，依次尝试以下操作：

1. 问一个知识性问题（例如「什么是 RESTful API？」）
2. 让 AI 生成一段代码（例如「用 Python 写一个简单的 HTTP 服务器」）
3. 使用 `/model` 命令查看当前模型信息
4. 使用 `/clear` 清空上下文，然后再问一个问题，观察 AI 是否还记得之前的对话

记录下每一步的结果，感受不同类型请求的响应差异。

**练习三：配置文件探索**

- `temperature: 0.2` 时，回复会更稳定、更确定
- `temperature: 1.0` 时，回复会更多样、更有创造性
