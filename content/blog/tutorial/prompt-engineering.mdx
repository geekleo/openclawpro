# OpenClaw Prompt 工程完全指南：从入门到精通

Prompt 是 OpenClaw 与 AI 模型之间的"通信协议"。一个好的 Prompt 可以让 AI 的输出质量提升数倍，而一个模糊的 Prompt 则会让你陷入反复调试的泥潭。本文将系统讲解在 OpenClaw 中编写高质量 Prompt 的方法论和实战技巧。

## 一、CRTE 框架：编写高质量 Prompt 的基础方法论

CRTE 是我们在大量实践中总结出的 Prompt 编写框架，它涵盖了高质量 Prompt 的四个核心要素：

### C — Context（上下文）

上下文告诉 AI "你是谁"和"你在什么场景下工作"。这是 Prompt 最基础也最重要的部分。

**为什么重要？** AI 模型对同一个问题的回答会因为上下文不同而截然不同。问"怎么处理这个错误"——如果上下文是"你是一位资深 Java 工程师"和"你是一位初学编程的大学生"，得到的回答在深度和表达方式上完全不同。

**最佳实践：**

```
你是一位拥有10年经验的金融合规审核专家。你熟悉中国银保监会和证监会的所有现行法规，
特别擅长识别金融产品说明书中的合规风险点。你的审核风格严谨细致，宁可误报不可漏报。
```

上下文的关键要素包括：
- **角色定位**：AI 应该扮演什么角色
- **专业背景**：该角色应该具备什么知识和经验
- **工作风格**：输出内容的风格偏好（严谨/轻松、详细/简洁等）
- **约束条件**：有什么限制和边界

### R — Requirement（需求）

需求是你希望 AI 具体做什么。需求越明确、越具体，AI 的输出就越接近预期。

**常见问题：** 很多人的 Prompt 需求部分过于笼统。"帮我写一篇文章"就是典型的模糊需求——什么主题？多少字？什么风格？面向什么读者？这些都没有说清楚。

**最佳实践：**

```
请根据以下信息，撰写一篇面向中小企业主的科普文章：
- 主题：企业如何选择适合自己的 SaaS 工具
- 字数：1500-2000字
- 结构：引言 + 3个选择维度（功能匹配度、成本效益、可扩展性）+ 总结
- 风格：通俗易懂，避免专业术语，多用类比和案例
- 目标：读完后读者能建立基本的 SaaS 选型框架
```

### T — Template（模板）

模板规定了 AI 输出内容的格式和结构。当你需要 AI 产出结构化内容时，提供明确的输出模板至关重要。

**为什么重要？** 在 OpenClaw 的自动化工作流中，AI 的输出通常需要被下游系统解析和处理。如果输出格式不固定，自动化流程就会断裂。

**最佳实践：**

```
请按以下 JSON 格式输出审核结果：

{
  "document_id": "文档编号",
  "review_date": "审核日期",
  "overall_result": "通过/不通过/需修改",
  "issues": [
    {
      "id": "问题编号",
      "location": "问题所在位置（页码/段落）",
      "severity": "critical/major/minor/info",
      "description": "问题描述",
      "rule_reference": "违反的规则编号",
      "suggestion": "修改建议"
    }
  ],
  "summary": "审核总结（100字以内）"
}
```

### E — Example（示例）

示例让 AI 直观地理解你期望的输出是什么样的。这就是所谓的 Few-Shot Learning 技术的核心——通过少量示例来引导 AI 的输出方向。

**最佳实践：**

```
以下是一个审核意见的示例：

问题：第12页第3段提到"本基金历史收益率达15%"
严重等级：critical
问题描述：直接展示历史收益率且未附带风险提示，涉嫌误导投资者
规则引用：《证券投资基金销售管理办法》第三十五条
修改建议：删除具体收益率数字，或在同一位置显著标注"过往业绩不代表未来表现"
```

CRTE 四个要素并非每次都需要完整使用。简单任务可能只需要 C + R，而复杂的结构化输出任务才需要完整的 C + R + T + E。

## 二、System Prompt 与 User Prompt 的区别

在 OpenClaw 中，Prompt 分为两个层级：System Prompt 和 User Prompt。理解它们的区别和各自适用场景是 Prompt 工程的基础。

### System Prompt

System Prompt 在 Skill 配置中定义，对所有会话生效。它的作用是设定 AI 的"基础人格"和"工作规范"。

```yaml
settings:
  system_prompt: |
    你是 OpenClaw 的智能运维助手。你的工作是监控系统状态、
    分析告警信息并给出处理建议。

    ## 工作原则
    1. 始终基于数据和日志进行分析，不要猜测
    2. 给出的处理建议必须包含具体的命令或操作步骤
    3. 对于可能影响生产环境的操作，必须标注风险等级
    4. 不确定的情况下，建议升级给人工处理

    ## 输出规范
    - 告警分析使用结构化格式
    - 处理建议按优先级排列
    - 所有命令使用代码块标注
```

**System Prompt 适合放什么内容：**
- 角色定义和专业背景
- 全局性的工作规则和约束
- 输出格式规范
- 安全相关的限制条件
- 不会频繁变化的静态信息

### User Prompt

User Prompt 是每次具体任务的输入，通常包含动态的上下文数据和具体的任务需求。

```yaml
user_prompt: |
  ## 当前告警信息
  告警名称：{alert_name}
  告警等级：{alert_severity}
  触发时间：{alert_time}
  告警详情：{alert_detail}

  ## 相关上下文
  最近1小时日志摘要：{recent_logs}
  当前资源使用率：CPU {cpu_usage}% / 内存 {mem_usage}%
  最近一次部署：{last_deployment}

  请分析此告警的可能原因并给出处理建议。
```

**User Prompt 适合放什么内容：**
- 当前任务的具体数据和参数
- 需要 AI 处理的输入内容
- 本次任务的特殊要求
- 动态变化的上下文信息

### 核心原则

**稳定的放 System Prompt，变化的放 User Prompt。** System Prompt 相当于岗位职责说明书，User Prompt 相当于每天的工作任务单。前者很少变，后者每次都不同。

一个常见错误是把所有内容都塞进 User Prompt。这会导致每次调用都发送大量重复的指令文本，既浪费 Token 又降低 AI 对关键信息的注意力。

## 三、结构化 Prompt 模板

以下是针对三种最常见使用场景的结构化 Prompt 模板。

```yaml
  {requirement_description}
```

```yaml
  {special_requirements}
```

## 四、上下文管理技巧

在 OpenClaw 的自动化工作流中，上下文管理是一个经常被忽视但至关重要的技巧。

### 1. Token 预算管理

每个 AI 模型都有上下文窗口的限制（如 GPT-4o 支持 128K Token）。虽然窗口很大，但这不意味着应该无节制地塞入信息。研究表明，当上下文过长时，AI 对中间部分信息的注意力会下降（即"Lost in the Middle"现象）。

**实践建议：**
- 将最重要的信息放在 Prompt 的开头和结尾
- 对长文本进行摘要后再传入，而不是原文直接粘贴
- 使用分段处理策略：先让 AI 提取关键信息，再基于关键信息进行分析

### 2. 动态上下文注入

在 OpenClaw 的 Skill 配置中，可以使用变量占位符动态注入上下文信息：

```yaml
user_prompt: |
  当前时间：{current_time}
  当前天气：{weather}
  用户历史偏好：{user_preferences}

  用户请求：{user_input}
```

这种方式确保每次 AI 都能获取最新的上下文信息，而不是依赖训练数据中的过时知识。

### 3. 多轮对话的上下文累积

对于需要多轮交互的场景（如客服对话），需要考虑上下文的累积管理：
- **滑动窗口**：只保留最近 N 轮对话的记录
- **摘要压缩**：定期对历史对话进行摘要，用摘要替代完整的历史记录
- **关键信息提取**：从历史对话中提取关键信息（如用户名、问题类型、已尝试的解决方案），以结构化的形式保留

```yaml
context_management:
  strategy: sliding_window
  max_turns: 10
  summarize_after: 5    # 超过5轮后对前面的对话进行摘要
  extract_key_info: true # 始终保留关键信息
```

### 4. 外部知识库集成

当 AI 需要的知识超出模型训练数据范围时，通过 RAG（Retrieval-Augmented Generation）模式注入外部知识：

```yaml
knowledge_base:
  source: "./knowledge/"
  search_strategy: semantic  # 语义搜索
  top_k: 5                   # 取最相关的5条
  inject_position: before_user_prompt  # 在用户Prompt之前注入
```

## 五、常见误区

在社区交流中，我们发现以下 Prompt 编写误区最为普遍：

### 误区一：指令过于笼统

**错误示范：** "帮我分析这份数据"

**正确做法：** "请从以下三个维度分析这份销售数据：1）月度环比增长趋势；2）各品类销售占比变化；3）客单价分布情况。输出包含核心发现和可操作建议。"

### 误区二：一次塞入过多任务

**错误示范：** "帮我分析数据、写报告、做PPT、发邮件"

**正确做法：** 将复杂任务拆分为多个步骤，每个步骤使用独立的 Prompt，通过 OpenClaw 的工作流串联起来。每个 Prompt 只做一件事，做好一件事。

### 误区三：忽略负面约束

只告诉 AI 要做什么，不告诉它不要做什么。

**补充负面约束：**
```
## 注意事项
- 不要编造不存在的数据和案例
- 不要使用"赋能"、"颠覆"等营销话术
- 不要给出超出专业范围的建议
- 如果数据不足以支撑结论，请明确说明
```

### 误区四：温度设置不当

温度（Temperature）控制 AI 输出的随机性。不同场景需要不同的温度：
- **数据分析、合规审核、代码生成** → 低温度（0.1-0.3），追求确定性和一致性
- **内容创作、头脑风暴、创意写作** → 中等温度（0.5-0.8），兼顾创造力和可控性
- **纯创意场景（诗歌、小说、广告文案）** → 较高温度（0.8-1.0），最大化创造力

### 误区五：不做版本管理

Prompt 像代码一样需要版本管理。每次修改 Prompt 后，记录修改内容和原因，对比修改前后的输出质量。这样才能系统性地提升 Prompt 质量，而不是每次都在凭感觉调整。

## 六、进阶技术

### Chain-of-Thought（思维链）

让 AI 在给出最终答案之前先展示推理过程，可以显著提升复杂任务的准确率。

```
请分析以下系统告警的根因。在给出结论之前，请先：
1. 列出所有可能的原因
2. 根据日志和监控数据逐一排查
3. 对每个可能原因给出概率评估
4. 最后给出最可能的根因和处理建议

请一步一步地思考。
```

思维链特别适用于以下场景：
- 故障诊断和问题排查
- 多因素决策分析
- 数学和逻辑推理
- 代码 Bug 定位

### Few-Shot Learning（少样本学习）

通过提供 2-3 个输入输出示例，让 AI 准确理解你期望的输出模式。

```
以下是几个告警分析的示例：

---
输入：CPU使用率持续超过90%，持续时间30分钟
分析：
- 可能原因：1) 流量突增 2) 内存泄漏导致频繁GC 3) 死循环或计算密集任务
- 排查步骤：检查流量曲线 → 检查JVM堆内存 → top命令查看进程
- 建议：先扩容缓解，同时排查根因
---

输入：数据库连接数突增至上限
分析：
- 可能原因：1) 连接泄漏 2) 慢查询阻塞 3) 流量突增
- 排查步骤：检查活跃连接 → 查看慢查询日志 → 检查连接池配置
- 建议：先重启连接池应急，同时检查应用层连接管理代码
---

现在请按相同格式分析以下告警：
输入：{alert_content}
```

Few-Shot 的关键技巧：
- 示例要有代表性，覆盖常见模式
- 示例数量通常 2-5 个即可，太多会浪费 Token
- 示例的格式要与期望输出完全一致

### Self-Consistency（自洽验证）

对于关键决策，让 AI 多次独立分析同一问题，然后比较结果的一致性。如果多次分析结论一致，可信度更高；如果结论分歧，则需要人工介入。

```yaml
# OpenClaw 中实现自洽验证的配置
verification:
  enabled: true
  rounds: 3           # 独立分析3次
  temperature: [0.2, 0.5, 0.3]  # 每次使用不同温度
  consistency_threshold: 0.8     # 一致性低于80%时标记为不确定
```

### Prompt Chaining（提示链）

将复杂任务拆分为多个 Prompt 环节，前一个环节的输出作为后一个环节的输入：

```
阶段1：信息提取
"从以下文档中提取所有数字数据和关键事实" → 输出结构化数据

阶段2：数据分析
"基于以下结构化数据进行趋势分析" → 输出分析结论

阶段3：报告生成
"基于以下分析结论撰写管理层摘要" → 输出最终报告
```

Prompt Chaining 的优势在于：每个环节的 Prompt 可以更简洁更精确，AI 的注意力更集中，最终的输出质量通常优于一次性的长 Prompt。

```
{feedback_list}

情感标注：正面 / 中性 / 负面
优先级：高 / 中 / 低

输出 JSON 数组格式，每条包含：原文摘要、分类、情感、优先级、建议处理方式。
```

## 总结

Prompt 工程不是玄学，而是一门可以系统学习和持续提升的技能。核心原则很简单：**给 AI 足够的上下文、明确的需求、清晰的格式要求和具体的示例**。

记住 CRTE 框架：Context（上下文）、Requirement（需求）、Template（模板）、Example（示例）。从简单场景开始练习，逐步积累经验，你的 Prompt 质量会稳步提升。

如果你有好用的 Prompt 模板或独到的经验，欢迎在社区分享。Prompt 工程是一个快速发展的领域，我们一起学习、一起进步。
