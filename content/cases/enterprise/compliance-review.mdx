# 某金融团队：合规文档自动审核

> "以前一份合规文档要三个人审三天，现在系统初审完成后，人工只需要复核关键条款，整体效率提升了至少五倍。" —— 合规部负责人 张总

## 场景痛点

这是一家中等规模的持牌金融机构，旗下业务涵盖基金销售、资产管理和财富顾问三大板块。合规部门共有 8 名审核人员，日常需要处理的文档类型包括：

- **产品说明书**：每份 30-80 页，涉及风险披露、费率说明、投资范围等数十个合规检查点
- **营销材料**：宣传单页、公众号文案、客户推介材料，需要确保不含违规承诺和误导性表述
- **合同协议**：客户签署的各类协议文本，需要与监管模板逐条比对
- **定期报告**：季报、年报中的信息披露完整性和准确性审核

在引入 OpenClaw 之前，团队面临以下核心痛点：

**审核周期长**：一份标准产品说明书的完整审核流程平均需要 3 个工作日。审核人员需要逐页阅读，对照最新的监管规则逐条检查，任何修改都需要重新走一遍流程。

**人为疏漏难避免**：合规审核高度依赖审核人员的经验和专注度。在高强度工作下，遗漏某条新出的监管细则、忽略某个隐含风险表述的情况时有发生。据内部统计，纯人工审核的漏检率约为 12%。

**规则更新滞后**：金融监管政策频繁更新，2025 年全年银保监会、证监会合计发布了超过 200 份监管文件。将新规则同步到每位审核人员的知识体系中，往往需要 1-2 周的学习和适应期。

**审核标准不统一**：不同审核人员对同一条款的理解存在差异，导致审核结果的一致性不足，内部经常出现"同一份文档，换个人审就有不同意见"的情况。

## 解决方案

合规团队基于 OpenClaw 搭建了一套完整的文档自动审核流水线，整体架构分为四个核心模块：

### 1. 文档解析模块

利用 OpenClaw 的文件处理能力，支持 PDF、Word、Excel 等多种格式的文档导入。系统自动提取文档结构，识别标题层级、表格数据、脚注引用等关键元素，将非结构化文档转化为结构化数据。

### 2. 规则引擎

将监管规则库按照业务类型、文档类型、检查维度进行分层组织。每条规则包含：规则编号、适用范围、检查逻辑、严重等级和引用法规原文。规则库支持版本管理，新规发布后可以在 1 小时内完成更新。

### 3. AI 审核核心

基于 OpenClaw 的 Prompt 编排能力，为不同审核场景设计了专用的审核 Prompt。AI 审核过程分为三轮：
- **第一轮：合规性扫描** —— 检查必备条款是否齐全、禁用词汇是否存在、数据引用是否准确
- **第二轮：逻辑一致性检查** —— 验证文档内部的数据是否自洽、前后表述是否矛盾
- **第三轮：风险预警** —— 识别潜在的合规风险点，标注需要人工重点关注的内容

### 4. 报告生成

审核完成后，系统自动生成结构化的审核报告，包含问题清单、风险等级、修改建议和法规引用，直接推送至合规人员的工作台。

## 关键配置

以下是合规审核 Skill 的核心配置示例：

```yaml
name: compliance-review
description: 金融合规文档自动审核系统
version: "2.1.0"

triggers:
  - type: webhook
    path: /api/compliance/upload
    method: POST
  - type: cron
    schedule: "0 9 * * 1-5"  # 工作日每天早上9点处理待审队列

settings:
  model: gpt-4o
  temperature: 0.1  # 低温度确保审核结果的一致性和确定性
  max_tokens: 8000

rules_engine:
  source: "./rules/financial/"
  categories:
    - product_disclosure    # 产品信息披露
    - risk_warning         # 风险提示
    - fee_transparency     # 费率透明度
    - marketing_compliance # 营销合规
    - contract_terms       # 合同条款
  severity_levels:
    critical: "必须修改，否则不予通过"
    major: "强烈建议修改"
    minor: "建议优化"
    info: "仅供参考"

review_pipeline:
  - step: document_parse
    config:
      supported_formats: [pdf, docx, xlsx]
      extract_tables: true
      extract_footnotes: true
      ocr_enabled: true  # 支持扫描件

  - step: compliance_scan
    prompt_template: |
      你是一位资深金融合规审核专家。请严格按照以下规则对文档内容进行逐条审核：

      ## 审核规则
      {rules}

      ## 待审核内容
      {document_content}

      ## 输出要求
      请按以下格式输出审核结果：
      1. 问题编号
      2. 问题位置（页码/段落）
      3. 问题描述
      4. 违反的规则编号
      5. 严重等级
      6. 修改建议

  - step: consistency_check
    config:
      check_data_consistency: true
      check_statement_contradiction: true
      cross_reference_validation: true

  - step: report_generation
    output:
      format: pdf
      template: "./templates/review_report.html"
      notify:
        - type: email
          recipients: ["compliance-team@company.com"]
        - type: webhook
          url: "https://internal.company.com/api/compliance/callback"
```

## 经验总结

经过半年的实践，团队总结了以下关键经验：

**1. AI 审核不是替代人工，而是增强人工**

系统定位为"AI 初审 + 人工复核"模式。AI 负责处理大量重复性、规则明确的检查项，人工专注于需要专业判断的复杂条款和边界案例。这种分工让合规人员从繁琐的逐条检查中解放出来，将精力集中在真正需要专业判断的地方。

**2. 规则库的持续维护是核心**

自动审核系统的准确率直接取决于规则库的质量。团队安排了一名专职人员负责监管政策的跟踪和规则库更新，确保系统始终与最新监管要求保持同步。

**3. 低温度 + 结构化输出是合规场景的关键**

在 Prompt 设计中，使用 0.1 的低温度确保审核结果的确定性和可重复性。同时，严格要求 AI 按照结构化格式输出审核意见，方便下游系统自动处理和人工复核。

**4. 建立反馈闭环持续优化**

每次人工复核中发现的 AI 漏检或误判，都会被记录并反馈到规则库和 Prompt 的优化中。经过 6 个月的迭代，系统的准确率从最初的 87% 提升到了 95% 以上。

**5. 合规留痕同样重要**

所有 AI 审核过程和结果都完整保存，包括使用的规则版本、AI 的原始输出、人工复核的修改记录等，满足监管对合规审核过程可追溯的要求。
