# 智能家居全屋联动：声控+自动化

> "以前回家要按6个开关、打开3个App，现在跟 Telegram 机器人说一句'我到家了'，灯光、空调、窗帘、音乐全部自动就位。" —— 智能家居玩家 老赵

## 场景痛点

老赵是一位资深的智能家居爱好者，三室两厅的家中安装了超过 50 个智能设备，涵盖灯光、空调、窗帘、门锁、传感器、摄像头、扫地机器人等多个品类。这些设备来自十几个不同品牌——小米、Aqara、涂鸦、飞利浦 Hue、Yeelight、博联、石头科技等等。

在引入 OpenClaw 之前，老赵的智能家居面临以下困境：

**App 碎片化严重**。手机里装了 8 个智能家居 App：米家、Aqara Home、涂鸦智能、Hue、博联智能……每个 App 只能控制自家的设备，想要关掉所有灯需要打开 3 个不同的 App。所谓的"智能家居"变成了"手机里多了一堆 App"。

**跨品牌联动困难**。虽然 Home Assistant 解决了设备统一接入的问题，但复杂的自动化场景编写起来很麻烦。Home Assistant 的自动化 YAML 语法对非程序员来说学习曲线陡峭，而且调试困难，经常出现"不知道为什么没触发"或"半夜突然执行了"的情况。

**语音控制体验差**。家里有小爱同学和天猫精灵两个语音助手，但各自只能控制对应生态的设备。更关键的是，这些语音助手只支持简单的指令（"打开客厅灯"），无法理解复杂的自然语言请求（"我要看电影了，帮我调整一下氛围"）。

**自动化场景死板**。基于时间和传感器触发的自动化规则是固定的，缺乏"智能"。比如设定了"天黑后有人进客厅就开灯"，但不管是白天窗帘拉着导致光线暗还是真的天黑了，传感器都会触发。

**家人操作门槛高**。老赵自己折腾得很开心，但家人（尤其是父母）觉得"还不如按开关方便"。复杂的 App 操作和语音指令让非技术用户望而却步。

## 解决方案

老赵用 OpenClaw 作为智能家居的"大脑层"，架构如下：Home Assistant 负责设备接入和底层控制，OpenClaw 负责自然语言理解、智能决策和场景编排，Telegram Bot 作为全家人统一的交互入口。

### 1. 设备统一接入

所有智能设备通过 Home Assistant 接入（支持 Zigbee、Wi-Fi、蓝牙、Matter 等多种协议），OpenClaw 通过 Home Assistant 的 REST API 获取设备状态和发送控制指令。设备清单按房间和类型组织，方便 AI 理解和操作。

### 2. 自然语言控制

通过 Telegram Bot 实现家庭成员的统一交互入口。每个家庭成员都可以用自然语言下达指令，AI 理解意图后调用相应的设备或场景：

- "太热了" → 自动判断当前室温，开启空调并设置合适温度
- "我要睡觉了" → 执行睡眠场景（关灯、关窗帘、空调调到26度、开启夜灯模式）
- "明天早上7点叫我起床" → 设置起床场景定时任务（渐亮灯光、播放轻音乐、打开窗帘）
- "家里有人吗？" → 查询各房间人体传感器和门锁状态，汇报结果

这种方式的好处是：**家人不需要记住设备名称和指令格式，用日常说话的方式就能控制全屋设备**。老赵的妈妈现在最喜欢的功能是跟机器人说"我要做饭了"，厨房灯、抽油烟机和背景音乐就自动开启。

### 3. 智能场景联动

不同于传统的"条件→动作"自动化，OpenClaw 可以基于多维度上下文进行智能决策：

- **时间上下文**：工作日和周末执行不同的场景
- **天气上下文**：接入天气 API，下雨天自动关窗、阴天提前开灯
- **人员上下文**：根据在家人数和成员（大人/小孩/老人）调整场景参数
- **历史习惯**：学习家庭成员的日常习惯，主动建议自动化规则

### 4. 异常检测与安全

AI 持续监控设备状态，识别异常情况：
- 离家模式下检测到门窗传感器触发 → 立即推送告警并调取摄像头画面
- 用电量异常飙升 → 检查是否有设备故障
- 水浸传感器告警 → 自动关闭水阀并通知
- 烟雾报警器触发 → 自动开启排气扇、关闭燃气阀、发送紧急通知

| 需要使用的 App 数量 | 8 个 | 1 个（Telegram） | **简化 88%** |
| 日均设备操作次数 | 手动 30+ 次 | 手动 5 次以下 | **减少 83%** |
| 家庭成员使用率 | 仅老赵 1 人 | 全家 4 人 | **100% 覆盖** |
| 已连接智能设备 | 50+ 个 | 50+ 个（全部纳管） | 统一管理 |
| 自动化场景数量 | 12 个（基础） | 35 个（智能） | **提升 192%** |
| 月均电费 | ¥680 | ¥476 | **降低 30%** |
| 场景触发准确率 | 75% | 95% | **提升 27%** |
| 异常告警响应时间 | 人工发现 | 实时推送 | **从被动到主动** |

电费降低 30% 的主要原因有三个方面：
1. **空调智能调控**：根据室温、体感温度和在室人数动态调整，避免无人时空调持续运行
2. **灯光自动管理**：离开房间自动关灯，根据自然光线调整亮度
3. **待机功耗管控**：深夜自动关闭不需要的设备电源，减少待机功耗

老赵的妈妈从最初的"还不如按开关"到现在每天主动跟 Telegram 机器人"聊天"控制家里的设备，这个转变是最让老赵惊喜的。自然语言交互把智能家居的使用门槛降到了几乎为零——不需要学任何 App、不需要记任何指令，就像跟家人说话一样自然。

一个温馨的细节：系统会根据天气变化主动提醒家人。某天预报有大雨，系统在下午 3 点自动给赵妈发了一条消息："阿姨，今晚有大雨，我已经帮您关好了阳台窗户，晾在外面的衣服可能需要收进来哦。"

## 经验总结

**1. Home Assistant 是设备接入的最佳选择**

不要试图让 OpenClaw 直接对接几十个设备的 API，那会非常复杂且不稳定。Home Assistant 在设备接入方面已经非常成熟，支持上千种设备和协议。OpenClaw 只需要通过 HA 的统一 API 来控制即可，各司其职。

**2. 自然语言控制是家庭场景的杀手级功能**

传统的按钮式和语音助手式控制都要求用户学习特定的交互方式，这对非技术用户是巨大的门槛。而自然语言理解让用户可以用自己的方式表达需求，AI 来负责翻译成设备操作。

**3. 安全操作必须有二次确认**

涉及门锁、报警系统、燃气阀等安全设备的操作，一定要设置二次确认机制。AI 可能会误解指令，这时候的"你确定要解锁大门吗？"至关重要。

**4. 循序渐进，从简单场景开始**

不要一开始就试图自动化所有场景。老赵的经验是从最常用的 3 个场景开始（回家、离家、睡觉），稳定运行一个月后再逐步扩展。过于激进的自动化反而会导致各种意外情况，让家人失去信任。

**5. 能耗监控带来意外收获**

原本只是顺手加上的能耗监控功能，没想到成了最实用的模块之一。可视化的能耗数据帮助全家人养成了节能意识，每月节省的电费虽然不多，但积少成多，一年下来也是一笔可观的数字。
